# Planted files in guardrail specs

A guardrail spec proves a rule (depcruise, eslint, tsc) by writing a violating source file and running the real tool on it. That file is a **plant**.

- One convention, one owner: `scripts/testing/plant.mjs`. A plant is any path with a segment containing `.planted` (`x.planted.ts`, `x.planted.testkit.ts`, `dir.planted/`).
- Create plants only through `plant(root, files)` (call `remove()` in `afterAll`/`afterEach`) or `withPlants(root, files, fn)` (removes in `finally`). The helper refuses names outside the convention and removes the directories it created.
- `scripts/glossary-lint.mjs` skips plants by asking `isPlanted`, the same function. Without that, a scan could read a half-written plant, hit ENOENT on a removed one, or lint a banned term planted on purpose (this reverted a land on 2026-09-30).
- `scripts/testing/plant.spec.ts` fails if a spec under `packages/` or `apps/` writes files without the helper.
- Plants are not gitignored on purpose: prettier and svelte-check honour `.gitignore` and must still see them.
- Bound the work, not the timeout (WP-143): a plant lives under `packages/` or `apps/` only for the length of one depcruise, eslint or tsc call. A proof that needs a long-running or repeating plant works in a temp root (`mkdtemp`); `scanRepo(roots)` takes absolute roots for this. To prove a type error fails in `apps/web`, run `tsc` with a temp tsconfig that extends the app's own and includes only the plant; the full `typecheck:web` runs once in `npm run check`.
- Specs under `packages/` and `apps/` use `withPlants` only, never `plant()` (WP-152). `plant()` creates now and removes later, so a spec that used it in `beforeAll` or at module level kept plants in the real tree for its whole file, while every other spec that scans the tree saw them. `plant.spec.ts` fails on such an import (it scans `packages/`, `apps/`, `e2e/` and `fixtures/`). `scripts/guardrails.spec.ts` is exempt: it plants per test through `plant()` and removes in `afterEach`, so each plant lives for one tool call.
- Plant paths are unique per spec (prefix with the spec's topic, e.g. `isolation-bare.planted.ts`). Two specs that plant the same path delete each other's file under a parallel run; `plant.spec.ts` fails on a shared path. It only sees full path literals; a path built from a template (console-rule's `${dir}/name`) cannot be compared statically, so give such directories a unique name too.
- A spec that scans the real tree (readdir/walk) skips plants with `isPlanted` (or walks a `mkdtemp` root). `plant.spec.ts` fails on a spec that recurses through directories (`readdirSync` with `isDirectory`/`withFileTypes`/`recursive`) without either.
- Whole-repo tools skip plants (WP-1022): prettier (`.prettierignore`), eslint (global ignores), depcruise (`boundaries` exclude) and every tsconfig (`exclude` of `**/*.planted*` and `**/*.planted/**` in the root, ui, builder, web and bench projects). A spec that needs a tool to see a plant passes `--no-ignore` (eslint), `--ignore-path /dev/null` (prettier) or writes a temp tsconfig with an explicit `include` and `exclude: []` (tsc).
