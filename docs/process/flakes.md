# Flakes and red lands

lead-c keeps this register. Every `Revert "Merge …"` on `main` gets a row: the spec, the symptom, the cause, and the status. Goal: red lands below 5% of lands.

Causes, in the order lead-c checks them:
- **flaky spec**: quarantine it with a tracked `it.skip` (comment naming the work package) plus a work package, or fix it in the tooling lane if it is test infrastructure
- **toolchain**: fixed in the tooling lane
- **merge skew**: two branches each green alone, red together (a signature changed on main after the branch forked). Not a flake: the branch needs `git merge main` and a re-land
- **real product bug**: a work package in the owning lane

## Silent reds (exit 1, zero failed tests)
A test run (vitest) can exit 1 with `failed: 0` and `failing: []`: a test file failed to load or collect, an unhandled error or rejection happened outside any test, or a worker crashed. `test-record` then writes a `silentRed` field into the `tests.jsonl` row (max 2 kB):
- `{ kind: 'suite', file, message }`: a suite that failed to load. Fix the import or setup error in `file`.
- `{ kind: 'unhandled', message }`: an unhandled error or rejection; the message starts at the vitest line that reported it.
- `{ kind: 'unknown', tail }`: nothing parseable; `tail` is the last ~40 lines of stderr (a worker exit or OOM shows up there).
Normal reds (failed tests) have no `silentRed`. Logwatch puts one `attention` line per silent red into its digest and raises an ALARM when the same file or reason shows up 3 times within 24 h.
