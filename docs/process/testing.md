# Testing

Built-app participant journeys (Pixel 7, de-DE, touch, the server's real security headers, a console/pageerror/CSP-violation listener that fails the test) live in `apps/web/e2e/participant/` and run in the `apps-web` suite: `npm run e2e -- --suite apps-web`, or `npx playwright test e2e/participant --repeat-each 3` from `apps/web` after `npm run build -w @ueberblick/web`. `world.ts` seeds the project; a test that changes personal preferences signs in as its own participant. Details on running suites: `docs/process/e2e.md`.

**Own packages (WP-1041).** Agent worktrees live inside the main checkout, so a worktree whose `node_modules` lacks the `@ueberblick/*` workspace links makes node resolve `@ueberblick/core`, `ui` and the rest from main, and its specs would test main's packages. `npm test` and `npm run check` / `check:changed` first run `scripts/ops/own-packages.mjs`: every workspace package must resolve (realpath) inside the checkout. If not, it runs the `deps:install` linker once and prints `own packages: relinked (…)`; if that fails it exits 1 (`rm -rf node_modules && npm run deps:install`). The check costs about 3 ms. The `check-steps.jsonl` rows carry `ownPackages: true`, and `check-recorded` ignores rows that say `false`.

**Guard specs always run (WP-1039).** `check:changed` adds the whole-tree guard specs to every selection, whatever the diff (`ALWAYS_SPECS` in `scripts/ops/changed-select.mjs`): plant, spec-env, guardrails, e2e-project-keys, lucide-imports, e2e-viewports, docsync guardrails, ui-strings-lint, parity (the evidence paths of `metrics/parity/elements.json`) and wp-ids (every `work/WP-*.md` has front matter `id:` equal to its file name, and no id is used twice: events, metrics and branches are keyed by it). No import reaches them, so before this their reds showed up only in the land train's full check, which refused six lands on 2026-10-04. They add about 14 s.
