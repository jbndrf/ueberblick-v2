# User documentation

This is documentation for the people who **use** Überblick. It is written for them, not for developers. It must match the current behaviour at all times (CLAUDE.md R16).

## Audiences and structure (Diátaxis)
```
docs/user/
  admin/          people who design and run projects in the builder
    tutorials/    learn by doing ("Your first project from a template")
    how-to/       one task each ("Give a role its own app", "Upgrade to a new template version")
    reference/    lookup (property types, rule-language functions, field options), generated from the schema where possible
    concepts/     understanding (features, tasks, runs, templates & overlays, offline)
  participant/    field users
    quick-start.md, how-to/…, troubleshooting.md (sync, offline, "my submission was refused")
```

## Rules
- The language is **German first** (the primary audience), with English following in `*.en.md`. Never leave one language knowingly outdated.
- Every user-visible change (UI, behaviour, wording, a new option) updates the affected page **in the same work package**.
- Screenshots are generated by a Playwright script in Phase 4+ (planned: `npm run screenshots`), never hand-made, so they stay current.
- Reference pages are generated from the Zod schema and registries wherever possible. Don't hand-write lists that exist in code.
- Keep pages short, one task per how-to, and use the words users see in the UI (the project labels and the generic German UI terms from the glossary).

## Quoting UI text (checked by `npm run lint:ui-strings`)
- A **label or message the app shows** is quoted: `"Submit"` in English pages, `„Absenden“` in German pages. A button or tab name may instead be **bold**; bold is not checked.
- The quoted text must exist in a message catalogue (`packages/*/messages/*.json`, `packages/tools/*/messages/*.json` or `apps/web/messages/*.json`): `*.en.md` pages are checked against English, all others against German. `{n}` in a message matches any text, a final full stop may be left out, and text ending in `…` or `...` abbreviates a longer message.
- Everything else is **not** quoted: code and data values go in `backticks`, examples, page titles and project labels in *italics*.
- **Escape.** If a quote of non-UI text is unavoidable, put `<!-- ui-strings-ignore -->` on that line. The comment is invisible when rendered. Use it rarely; every use is a place the lint cannot protect.
- Text inside `backticks` and fenced code blocks is never checked.
