# Ein Projekt erstellen

Jedes angemeldete Admin-Konto kann ein Projekt in einem Schritt anlegen. Sie finden es auf der Seite **Projekte** (erste Seite nach der Anmeldung).

**Auf dem Bildschirm:** Die Seite zeigt eine Karte je Projekt mit Name, Beschreibung (ohne Beschreibung: das Erstellungsdatum nach „Erstellt“) und **Projekt öffnen**. **Projekt erstellen** (oben rechts) fragt nach Projektname, Beschreibung und Vorlage; **Leeres Projekt** steht an erster Stelle. Ein leerer Name ergibt „Der Name ist erforderlich“. Danach landen Sie auf der Seite **Teilnehmende** des neuen Projekts.

**Über die Schnittstelle** (dieselben Schritte, die der Bildschirm nutzt):

1. **Vorlage wählen.** `GET /api/admin/templates` liefert die veröffentlichten Vorlagen, je Schlüssel die neueste Version, **Leeres Projekt** (`leer`) zuerst, mit deutscher und englischer Bezeichnung.
2. **Anlegen.** `POST /api/admin/projects` mit `{ "name": "Baumkataster Nord", "description": "…", "template": "leer@1" }`. Die Antwort (201) nennt `id` und `key`. Den Schlüssel erzeugt Überblick aus dem Namen (Umlaute werden ausgeschrieben, bei einem doppelten Namen kommt eine Nummer dazu). Ein leerer Name oder eine unbekannte Vorlage ergibt 400 mit den betroffenen Feldern. `GET /api/admin/projects` liefert die Projekte, in denen Sie Mitglied sind, neueste zuerst: `id`, `key`, `name`, `description`, `createdAt`, `template` (`schluessel@version` der bereitgestellten Version, sonst `null`) und `published` (erst nach der ersten Bereitstellung `true`).
3. **Konfigurieren.** Das Projekt hat sofort einen **Entwurf** aus der Vorlage und Sie sind Mitglied. Es ist aber noch nichts live: erst **Veröffentlichen** (siehe [Ein Projekt bereitstellen](deploy.md)) macht die erste Version daraus.

## Menü auf der Seite Projekte

Der Aufklappknopf neben **Projekt erstellen** und der ⋮-Knopf auf jeder Karte enthalten die Aktionen für Projektdateien.

- **Aus Datei importieren** (Pfeil neben **Projekt erstellen**): wählen Sie eine Projektdatei (`.yaml`, `.yml` oder `.json`, bis 1 MB). Eine Datei, die eine veröffentlichte Vorlage erweitert, wird der Entwurf des neuen Projekts. Eine vollständige Vorlagendatei wird zuerst als Vorlagenversion veröffentlicht und das Projekt darauf aufgebaut. Das neue Projekt ist erst nach dem ersten **Veröffentlichen** live. Hat die Datei Probleme, zeigt eine Liste jedes mit seiner Stelle in der Datei, und es wird kein Projekt erstellt.
- **Schema exportieren** (⋮ auf einer Karte): lädt den aktuellen Entwurf des Projekts, Vorlage und Änderungen zusammen, als eine YAML-Datei mit dem Namen des Projekts. Importieren Sie diese Datei auf einer anderen Instanz, entsteht ein gleiches Projekt.
- **Als Vorlage veröffentlichen** (⋮ auf einer Karte): braucht ein Projekt, das mindestens einmal veröffentlicht wurde. Der Dialog fragt nach dem Namen der Vorlage, einem Schlüssel (zu Beginn der Projektschlüssel) und einer Version (zu Beginn die nächste Nebenversion dieses Schlüssels, sonst 1.0.0). Die Version erscheint danach in der Vorlagenliste von **Projekt erstellen**. Eine Versionsnummer kann nur steigen, und innerhalb einer Hauptversion darf nichts entfallen.

- **Gesamtes Projekt exportieren (ZIP)** (⋮ auf einer Karte): lädt ein Archiv mit der Projektdatei, allen Objekten jeder Objektart (in jedem Zustand, auch archiviert und gelöscht) und allen Anhängen. Es geht auch für ein Projekt, das noch nie veröffentlicht wurde; dann enthält es nur die Projektdatei. Auch die Teilnehmenden sind dabei: mit Rollen, eigenen Spalten, Status und ihrem **Zugangstoken**, damit bestehende Logins und QR-Codes auf der neuen Instanz weiter funktionieren (Administrator-Konten sind nicht dabei). **Die Datei enthält Zugangsdaten: bewahren Sie sie vertraulich auf und geben Sie sie nicht weiter.** Das Archiv ist eine Sicherung des heutigen Stands, nicht des Verlaufs: wer ein Objekt wann geändert hat, steht nicht darin. Gelöschte persönliche Daten bleiben gelöscht.
- **Daten exportieren (CSV)** (⋮ auf einer Karte, nach der ersten Veröffentlichung): lädt ein ZIP mit einer CSV-Datei je Objektart, mit den Spalten der Datenseite, Komma als Trenner und der Position als `lon` und `lat`. Ausgeblendet sind gelöschte Objekte, wie auf der Datenseite.
- **GeoPackage exportieren** (⋮ auf einer Karte, nach der ersten Veröffentlichung): lädt ein GeoPackage mit einer Ebene je Objektart, in WGS84.
- **Gesamtes Projekt importieren (ZIP)** (Pfeil neben **Projekt erstellen**): wählen Sie ein Archiv. Der Dialog nennt Datei und Größe und lässt Sie einen anderen Namen vergeben; **Importieren** lädt hoch und legt das Projekt an. Enthält das Archiv Objekte, wird das Projekt dafür sofort veröffentlicht, weil Objekte eine Konfigurationsversion brauchen; ohne Objekte bleibt es ein Entwurf. Ein Fortschrittsbalken zeigt Hochladen und Verarbeiten, Sie können den Dialog schließen, der Import läuft weiter. Enthält das Archiv Teilnehmende, werden sie mit ihren Zugangstokens wiederhergestellt. Ein Token gibt es auf einer Instanz nur einmal: wird ein Token des Archivs schon verwendet (zum Beispiel im Original-Projekt derselben Instanz, wenn Sie eine Kopie anlegen), bekommen diese Teilnehmenden neue Zugangslinks, alle anderen behalten ihren; der Dialog nennt die Zahl („n Teilnehmende haben neue Zugangslinks erhalten“). Die Logins des Originals bleiben unverändert. Kommt ein Token im Archiv selbst mehrfach vor, ist das Archiv beschädigt und der Import wird abgelehnt. Archive ohne Teilnehmende (ältere Exporte) importieren wie bisher ohne Teilnehmende. Scheitert er, nennt der Dialog die Gründe und das dabei begonnene Projekt wird wieder entfernt (wie beim Löschen eines Projekts); es bleibt nichts Unvollständiges zurück. Das Archiv wird beim Entpacken streng begrenzt (höchstens 4 GB entpackt, 2 GB je Datei, 4 MB für Projektdatei und Manifest, 4 MB je Zeile einer Datendatei); ein Archiv, das mehr entpackt, als es angibt, wird sofort abgelehnt. Die Vorlage der Archivdatei wird als eigene Vorlage `import_…` veröffentlicht, wenn es ihren Namen mit anderem Inhalt schon gibt. Größte Datei: 2 GB, aber höchstens das `UPLOAD_LIMIT` der Instanz (Standard 50 MB); für größere Archive setzen Sie einen höheren Wert.

Über die Schnittstelle: `POST /api/admin/templates` (`project`, `key`, `version`, `label`), `GET /api/admin/projects/<project>/schema` und `POST /api/admin/projects/import` (multipart `file`); für die Archive `GET /api/admin/p/<project>/export/zip`, `…/export/csv` (mit `?type=<Objektart>` eine einzelne CSV-Datei), `…/export/gpkg`, `POST /api/admin/projects/import-zip` (das ZIP als Anfragekörper, optional `?name=`) und `GET /api/admin/projects/import-zip/<job>` für den Stand.

Der Betreiber kann Projekte weiterhin mit `npm run admin -- create-project` anlegen.
