# Information architecture map (living document)

> **Being replaced (2026-10-01).** The participant section below is the ported v3 map screen (WP-620). The builder sections still describe the first v4 UI (lenses, `/builder`), which is being replaced by the owner's v3 navigation (`docs/process/rebuild.md`). Each ported screen rewrites its rows here.

This is the single source of **where every function lives** in the UI (docs/13, principle 2). UI work packages update it in the same change. The lead approves structural changes and records new top-level entries as later topics (`docs/decisions/later/`) for the owner to review after the build.

## Participant app (the owner's v3 map screen, WP-620)
One working screen, `/map` (the first-build `/app`, its view chips, status indicator, "Me" area and bottom navigation are gone). Composed in `apps/web/src/lib/participant/shell` (header, map canvas, bottom bar, sheet host); the map is the headless MapLibre renderer of `packages/ui/src/map`. Sign-in at `/login` comes before it and is no area. So is the public guest link `/join/<slug>` (WP-639, v3's `/join/[slug]`): a card (logo, "Als Gast beitreten", one button) that submits itself, signs a guest in and lands on `/map` = 0 taps (1 without scripts); an unknown link is 404 "Nicht gefunden.". Every other function is a **sheet over the map**, opened through the registry `shell/sheets.ts` (one line per ported sheet; a slot with no entry opens nothing and its button stays). Navigation depth: 1 (the map) plus sheets, which count as no level.

Sign-in is `/login` (WP-609, v3's card: Token-Anmeldung tab, QR-Code tab with in-app scanner and image upload, `/login?token=` signs in with 0 taps); an empty token shows v3's field error under the input, the page body does not scroll (WP-651).
