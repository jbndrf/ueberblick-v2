# A-033 Tile proxy: browsers never talk to a tile provider, and packs warm the same cache
priority: high        status: provisional contract (lead-a); follows the owner's answer P5 (2026-10-02)
date: 2026-10-02   lead: a (server), b (wires the map), c (CSP, WP-957)   work packages: WP-369   touches: A-032, H1, H6 / R13 / R14 / docs/12

## Context
The owner answered P5 (QUESTIONS.md): packs ideally come from hosted tiles; v3's server-side tile cache proxy (`reference/src/lib/server/tile-cache.ts`, `/api/tiles`, `/api/wms`) must be ported so that browsers never talk to third-party tile providers (GDPR); packs warm the same cache, which makes OSM-based layers unproblematic for packs too. With the proxy, proxied layers need no external origin in the CSP.

## Chosen (provisional)
1. **Endpoints** (participant or admin session, 401 without; the layer must be visible to the caller through `layersForRoles`, the one audience rule, else 404, as the pack download does):
   - `GET /api/p/<project>/tiles/<layer>/<z>/<x>/<y>` for `xyz`, `preset` and `pmtiles` layers. `<layer>` is the key in `map.layers`. `<y>` may end in a format (`5.png`) so a GIS client can use the URL as it is. `z` is 0 to 24, `x` and `y` are below 2^z, else 404.
   - `GET /api/p/<project>/wms/<layer>?bbox=w,s,e,n&width=&height=&crs=` for `wms` layers (`srs` is read as `crs`; default `EPSG:3857`). **Only these four pass on.** The layer's own `layers`, `version`, `format` and `transparent` come from the config, `service=WMS`, `request=GetMap` and `styles=` are fixed, and every other query parameter is dropped (no `sld`, no `sld_body`, no `layers` override). `bbox` is four finite numbers, `width` and `height` are integers from 1 to 2048 (`TILE_PROXY_LIMITS.wms_max_pixels`), `crs` is `EPSG:<digits>`, else 400. A query already on the configured WMS URL (a capability token) stays.
   - `geojson` is not proxied (the map loads data, not tiles). A layer of another type on a route gives 404.
2. **Resolution** of one tile: the disk cache, else the upstream (a URL template with `{z}`, `{x}`, `{y}` and optional `{s}`; a PMTiles archive by range; a WMS GetMap). The upstream answer must be a real image (recognised by its first bytes, not by the `Content-Type`), else it is an error and nothing is kept. Concurrent requests for one tile share one upstream fetch.
3. **Answers.**
   - 200 with the tile, `Content-Type` of the bytes, `Cache-Control: private, max-age=86400` (`browser_max_age_s`), `ETag`, `Vary: Cookie`, `X-Tile-Cache: HIT|MISS`; 304 on `If-None-Match`.
   - 404 when the upstream has no such tile (404 or 410), nothing cached.
   - 502 (`upstream_failed` in the error envelope) when the upstream fails after its retries, nothing cached.
4. **Cache.**
   - Files under `<dataDir>/tiles-cache/<project>/<source key>/<z>/<x>/<y>.<ext>` (WMS: `<source key>/wms/<request hash>.<ext>`). The **source key** is the first 32 hex characters of the SHA-256 of the canonical JSON of the layer's source (type and URL template; for a preset its resolved template; for WMS URL and declared parameters). A changed source gets a new directory and never serves the old source's tiles. The old directory is trimmed by the size cap, never read again.
   - **Atomic writes:** temp file next to the target, then rename. A reader sees the old file, no file or the whole new one.
   - **Size cap** `cache_max_bytes` (2 GB, registry `TILE_PROXY_LIMITS`): an in-memory index (path, size, last use) is built by one scan at the first write; a write that crosses the cap trims the least recently used files down to 90%. A read touches the index only to note the use.
   - **Age:** a tile older than `cache_max_age_s` (30 days) is fetched again. The age rides on the file's mtime, so no sidecar file is read: a tile whose upstream says `Cache-Control: s-maxage=N` (the proxy is a shared cache, so it wins over `max-age=N`; `no-cache` means N = 0) is written with `mtime = now + N - max_age`, so it goes stale after N seconds; `no-store` and `private` upstream answers are served but not kept. The browser's `Cache-Control: private, max-age` is `min(browser_max_age_s, remaining freshness of the cached tile)`, so a browser never keeps a tile longer than the upstream allows (WP-1069).
5. **Upstream politeness.**
   - **One limiter per upstream host**, shared by the proxy and the pack builder: at most 2 requests in flight and 10 starts per second (`upstream_concurrency`, `upstream_per_second`).
   - User-Agent `Überblick/4 (+<PUBLIC_URL>)`, one builder (`tileUserAgent`) for the proxy, the pack tile fetches and the pack range fetches (the pack fetch used `Überblick-PackBuilder/4` before).
   - Up to 3 retries with exponential backoff (500 ms, doubled) on network errors, 5xx and 429; a `Retry-After` (seconds or date, at most 30 s) holds back every request to that host through the limiter.
6. **Packs.**
   - `MAP_SOURCE_TYPES` gets a second flag `proxied` (xyz, wms, pmtiles, preset: true; geojson: false) and **`packable` becomes true for `xyz` and `preset`** (it was `pmtiles` only). WMS stays unpackable (a render per request, not tiles); geojson is data.
   - The pack builder reads an `xyz` or `preset` layer tile by tile through the same tile service (`PackTiles`), so a build fills the cache and the proxy then serves that region with no upstream call. A tile the source does not have is left out; an upstream that fails after its retries fails the layer (`failed(reason)`, resumable). The output is a PMTiles file of the raster tiles, with the tile type read from the first tile.
   - `pmtiles` sources keep the range reader of WP-350 (`fetchRange`). That reader has its own concurrency limit and does not use the host limiter yet (follow-up in the WP Notes).
7. **OSM usage policy.** The OSM tile usage policy discourages bulk downloads, so a pack stays a small regional extract: the registry `TILE_HOST_POLICIES` caps the tiles one (pack, layer) may fetch from a host, **10,000 for `tile.openstreetmap.org` and its subdomains**, whether the layer is `preset: osm` or an `xyz` URL on that host. The build checks the real tile count before it fetches one tile and fails the layer with the reason (make the area or the zoom range smaller). With the limiter (at most 10 tiles per second) a capped pack takes about 17 minutes and happens once, because the cache then holds it. Pack definitions above the general pack limits are still refused by the checker (`PACK_LIMITS`). The checker does not know the host cap yet (it is enforced in the build; a checker problem for it is a follow-up).
8. **CSP.** The layer kinds that are proxied (registry flag `proxied`): `xyz`, `wms`, `pmtiles`, `preset`. Their upstream origin needs no `img-src` or `connect-src` entry once lead-b serves the map from the proxy URLs. Only `geojson` layers still load from their own URL.
9. **SSRF guard (review round 1).** A layer URL is admin-authored, but the proxy must not become a way into the server's network. One guard (`tiles/guard.ts`, `address.ts`, `pinned-fetch.ts`) judges every request to a layer's host: the proxy upstream, the pack tile fetches and the pack range fetches (`httpFetchRange` gets the guard's fetch), and the pack readers check the source before the build starts (R1).
   - **Resolve once and pin.** The host is resolved once; every returned address must be public, else the host is refused (one private answer among public ones refuses it). The connection goes to the validated address (`http(s).request` with a pinned `lookup`), with the Host header and the TLS server name still the host's, so DNS cannot change between check and connect.
   - **Refused ranges:** 0/8, 10/8, 100.64/10, 127/8, 169.254/16 (cloud metadata), 172.16/12, 192.0.0/24, 192.168/16, 198.18/15, 224/4 and 240/4; `::`, `::1`, fc00::/7, fe80::/10, ff00::/8; IPv4-mapped (`::ffff:a.b.c.d`) and NAT64 (`64:ff9b::/96`) addresses by the IPv4 address they carry. A literal IP in the URL is checked the same way.
   - **The instance itself** (the host of `PUBLIC_URL`) is refused by name. A layer URL that is a path on this instance (`/…`, `isSameOriginPath`) is **self-hosted** (round 2, provisional, cheapest to undo): it never leaves the instance, so there is nothing to proxy and no GDPR issue. The tile and WMS routes answer 404 `not_proxied` (HTTP error registry) and the renderer loads it directly; the pack builder and readers read it against the origin (`PUBLIC_URL`) through `httpFetchRange`'s `originFetch`, without the guard (the URL is built by us from origin plus path, unauthenticated, so it reaches only what the public can; an xyz template is read tile by tile the same way, a tile that answers 404 is absent, as for a remote xyz, round 3). `isSameOriginPath` is strict (round 3): `/` then a char that is not `/` or `\`, and no backslash or control character anywhere, because the URL parser reads `\` as `/` and drops tab and line breaks (`/\evil.com` would leave the origin); `httpFetchRange` also checks the resolved origin. A protocol-relative `//host/…` is not a path: it stays absolute and guarded (`bad_url`). `own_host` stays for absolute URLs that name this instance.
   - **Redirects** are followed by hand, at most 3 hops, and every hop passes the check; a redirect to a private address is refused.
   - **Refusal** is a typed `UpstreamRefused` (`UPSTREAM_REFUSALS`: `bad_url`, `private_address`, `own_host`, `unresolved`, `too_many_redirects`). It happens before any request and is never retried; the tile answers 502 (nothing cached) and a pack layer fails with the reason.

## Seams (R13)
- H6 (external GIS): the proxy is a stable, authenticated tile URL that QGIS can use (session cookie today; a token is the same seam as the OGC API).
- H1 (3D, terrain): another source type is a registry entry with its own `packable` and `proxied` flags and a resolver in `tiles/source.ts`, with no shape change.
- A second upstream protocol (WMTS) is another resolver and nothing else.

## Rejected
- **Caching in the database.** Tiles are bytes by key; files are the cheapest, they stream, and eviction is a delete.
- **A cache keyed by layer key.** A layer's source can change under the same key (an admin edits the URL), and stale tiles of the old source would be served.
- **Sending the browser's IP address or headers upstream.** v3 dropped them, and so does this: the upstream sees the server only.

## Not decided here
- The size of the cap and the limits are registry values, not settings; the operator can ask for different ones later.
- Whether a layer URL on a private network should ever be allowed (an intranet tile server): refused for now, see item 9. An allow-list per project would be a registry or config addition and nothing else.
